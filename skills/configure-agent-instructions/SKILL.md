# Configure agent instructions

Read [working rules](references/workflow.md) and [document selection](references/documents.md). Adapt the bundled [AGENTS.md](templates/AGENTS.md), [README](templates/README.md) and optional [architecture document](templates/docs/architecture.md) to the target. Templates are source material, not mandatory files to overwrite.

## Procedure

1. Read applicable instructions, README, specifications, existing task tracking and completed evidence. Inspect staged and unstaged Git changes. Identify actual development commands, document locations, runtime and package manager without installing or changing tooling. Identify the AI coding tools the target uses from its instructions, existing configuration and the user's stated setup. Distinguish installed tools from active hosts and preserve existing project and user settings.
2. Identify missing core rules and their owning documents using the working rules. Merge a concise project overview, architecture boundaries, workflow obligations, coding standards, verification principles/actual commands, document responsibilities and security/authorization rules into the applicable existing AGENTS.md, or create a minimal one when absent. Preserve project decisions and instruction precedence. Adapt the recommended structure to the target. Link existing procedures rather than copying task lifecycle, gates or resume checklists into AGENTS.md. Keep Tailwind guidance only for targets using it.
3. Keep instructions concrete. Replace every placeholder with target values or an explicit reason for absence. Reference actual commands; never invent passing checks or nonexistent scripts. Keep deployment, branches, workspace names, package manager and commit scopes as target decisions.
4. Apply the document responsibilities in the working rules. Before shortening existing instructions, preserve every applicable safeguard in its owning target document and leave a mandatory reference in AGENTS.md. Reuse sufficient existing playbook/tracker guidance; merge only missing procedures there. If no procedure document is needed, keep a concise actionable fallback in existing instructions or the request checklist rather than forcing a new file. Keep README as a current-state entry point, linking existing architecture, tooling and task documents instead of duplicating their content. Keep simple architecture and tooling information there when no separate document is needed. Create a separate architecture document only when useful; use ADRs only when significant decisions need historical rationale. Preserve existing task tracking, completed tasks and meaningful evidence in their owning documents. If no concrete work is planned, state that rather than creating empty phases or requiring nonexistent indexes.
5. Tailor the [agent efficiency policy](references/workflow.md#agent-efficiency-and-model-routing) to the target's typical work, scale, coordination needs and verification cost. Merge the core rules into applicable instructions and reuse an existing target guidance document for additional detail when needed. For Codex or Claude Code, use the [model routing reference](references/model-routing.md) to confirm discovery, support and effective settings for the installed host. Propose or minimally merge target-scoped agent configuration only when it serves a concrete need, support is confirmed and the requested scope authorizes it. Keep existing values and report conflicts or unsupported options. Guidance alone is sufficient when the host is unknown, configuration is out of scope or direct execution meets the need.
6. Review instruction consistency, resolved placeholders and local document references through reads/searches. Compare the original and revised instructions for safety coverage and duplicate ownership. Ensure linked procedures remain accessible without installed skills; never point target instructions at an absent skill or repository-root guide. If agent configuration changes, review the merge and confirm discovery and effective settings in the target when an applicable host check is available and authorized. Run target executable checks only when the actual authorized change requires them. Distinguish document review from behavioral verification.

## Completion and boundaries

Deliver customized persistent instructions and useful navigation, with no dependency on this skill remaining installed. Report changed files, routing and delegation decisions, optional settings applied or omitted, unresolved project decisions and review limits. Record the source skill/repository reference with full SHA, or identify an uncommitted local path. Do not configure lint/format/hooks, install dependencies or turn requirements into feature tasks under this request. Those are separate tasks unless the user also requests them. Do not commit, create remotes, push or deploy without authorization.
