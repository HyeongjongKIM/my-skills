# Official research entry points

Use these sources when adopting or changing target configuration. Follow documentation for the selected releases, then inspect current release maintenance, official security advisories, package engines and peer metadata. Links are research entry points, not a certified version combination. Record decision-relevant findings once in the task, README or optional tooling document; a separate research table is not required.

| Area | Official sources | What to establish |
| --- | --- | --- |
| ESLint | [Flat Config](https://eslint.org/docs/latest/use/configure/configuration-files), [duplicate imports](https://eslint.org/docs/latest/rules/no-duplicate-imports), [version support](https://eslint.org/version-support/) | Config shape, file scopes, separate type imports and maintained releases |
| TypeScript lint | [Typed linting](https://typescript-eslint.io/getting-started/typed-linting/), [rules](https://typescript-eslint.io/rules/), [dependency support](https://typescript-eslint.io/users/dependency-versions/), [troubleshooting](https://typescript-eslint.io/troubleshooting/typed-linting/) | Rule APIs, project service, tsconfig coverage and supported compiler/linter ranges |
| Source filenames | [Unicorn filename-case](https://github.com/sindresorhus/eslint-plugin-unicorn/blob/main/docs/rules/filename-case.md), [plugin usage](https://github.com/sindresorhus/eslint-plugin-unicorn), [releases](https://github.com/sindresorhus/eslint-plugin-unicorn/releases) | Supported filename-rule options, ESM/engine/peer requirements and selected-release behavior |
| TypeScript | [TSConfig reference](https://www.typescriptlang.org/tsconfig/) | Runtime-appropriate module/JSX configuration and project boundaries |
| Formatting | [Prettier configuration](https://prettier.io/docs/configuration), [ignores](https://prettier.io/docs/ignore), [eslint-config-prettier](https://github.com/prettier/eslint-config-prettier) | Independent formatting, selected style options and conflict disabling |
| Optional Tailwind format | [Plugin author](https://github.com/tailwindlabs/prettier-plugin-tailwindcss) | Plugin order and stylesheet/configuration discovery |
| VS Code | [TypeScript](https://code.visualstudio.com/docs/typescript/typescript-transpiling), [source schema](https://github.com/microsoft/vscode/blob/main/extensions/typescript-language-features/package.json), [ESLint extension](https://github.com/microsoft/vscode-eslint), [Prettier extension](https://github.com/prettier/prettier-vscode) | Installed-release settings, local tool resolution, save behavior and workspaces |
| Hooks | [Husky setup](https://typicode.github.io/husky/get-started.html), [how-to](https://typicode.github.io/husky/how-to.html), [lint-staged](https://github.com/lint-staged/lint-staged) | Supported installation, user hook bodies, file matching and partial-staging protection |
| Commits | [Commitlint setup](https://commitlint.js.org/guides/getting-started.html), [configuration](https://commitlint.js.org/reference/configuration.html), [local hook](https://commitlint.js.org/guides/local-setup.html), [CI](https://commitlint.js.org/guides/ci-setup.html), [Conventional Commits](https://www.conventionalcommits.org/en/v1.0.0/) | Preset, actual message checks and CI commit ranges |
| Runtime and manager | [Node release support](https://nodejs.org/en/about/previous-releases), [npm exec](https://docs.npmjs.com/cli/commands/npm-exec/), [pnpm installation](https://pnpm.io/installation) | Supported runtime and the target manager's local execution/install semantics |
| Security research | [GitHub Advisory Database](https://github.com/advisories), [npm audit](https://docs.npmjs.com/cli/commands/npm-audit/), [pnpm audit](https://pnpm.io/cli/audit) | Relevant advisories and target-manager checks; use package owners' official advisories as primary evidence |
| Reuse | [GitHub licensing guidance](https://docs.github.com/en/repositories/managing-your-repositorys-settings-and-features/customizing-your-repository/licensing-a-repository) | Public access does not establish redistribution permission |

[Astro](astro.md) and [React](react.md) link their own technology-specific official sources. No particular React bundler or test runner is required. Compatibility metadata alone does not establish security maintenance, runtime behavior or successful target verification.
