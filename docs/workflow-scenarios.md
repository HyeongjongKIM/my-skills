# Workflow scenario review

These are document walkthroughs, not executed agent evaluations, application tests or host installation tests. The review follows each input through the linked instructions and records the prescribed outcome. Use the cases when reviewing future guidance changes; actual enforcement requires target-project tooling and behavioral evidence.

| Input / scenario | Document path reviewed | Prescribed outcome / review result |
| --- | --- | --- |
| Normal project: requirements map to tasks, prerequisites are satisfied, behavior and mandatory checks are evidenced | [Project](../playbooks/project-development.md), [gates](../playbooks/gates.md) | Sequential acceptance checks followed by source-requirement comparison permit COMPLETED within the agreed scope. Planning alone does not. |
| Plan includes login but omits the requested password recovery flow | [Planning coverage](../skills/plan-implementation/references/planning.md#requirement-coverage-and-planning-quality-gate) | Original request comparison exposes an unmapped requirement. Add bounded work and verification before declaring the plan ready; no task-count quota. |
| All tasks are DONE, but the requested export feature has no working implementation | [Completion Gate](../playbooks/gates.md#completion-gate) | Original requirements override queue appearance. Add missing work with a new ID; report PARTIAL instead of COMPLETED. |
| Two tasks require incompatible API response contracts during implementation | [Feedback](../playbooks/gates.md#feedback-during-execution) | Report locations, cause, affected consumers/tasks and alternatives. Block dependent work, obtain any material contract decision and continue eligible independent work; recheck the revised plan. |
| Task 03 went IN_PROGRESS, returned to TODO, and insertion suggests renaming it 04 | [Stable identity](../skills/plan-implementation/references/planning.md#stable-identity-and-history) | Preserve 03 and transition history; allocate an unused ID. All IDs are protected from creation, including TODO and cancelled tasks. |
| Earliest phase is blocked but a later task has no dependency on it | [Queue](../skills/plan-implementation/templates/tasks/README.md), [target instructions](../skills/configure-agent-instructions/templates/AGENTS.md#development-workflow) | An unrelated phase blocker must not stop eligible work. The queue and target instructions agree that all explicit task and phase prerequisites must be satisfied before independent work proceeds. |
| A TODO task is cancelled, then its ID is requested for new work | [Identity and lifecycle](../skills/plan-implementation/templates/tasks/README.md#identity-and-lifecycle) | Retain the cancelled record, ID and history; allocate a new ID. Cancellation never satisfies a dependency. |
| A task is split or merged | [Stable identity](../skills/plan-implementation/references/planning.md#stable-identity-and-history) | Keep original IDs, evidence and successor links; update dependents to actual replacement tasks. Supersession cannot fabricate DONE or satisfy prerequisites. |
| A completed feature receives a new permission requirement | [Continuous planning](../skills/plan-implementation/references/planning.md#continuous-planning-and-handoff) | Preserve historical completion, add a linked new task and reassess affected requirements/checks. Evidence disproving the old result permits an explained correction, not an erased history. |
| Required regression test fails, or the environment cannot run it | [Completion Gate](../playbooks/gates.md#completion-gate) | Record actual failure or not-run reason and risk; no passing claim. PARTIAL while implementation/verification remains, BLOCKED if a material constraint prevents progress. Independent work can continue. |
| Codex session ends with a half-edited task and then restarts | [Checkpoint and resume](../skills/plan-implementation/templates/tasks/README.md#checkpoint-and-resume), [Codex](harness/codex.md) | Existing checkpoint links current work, decisions, blockers and checks; resume inspects Git changes and relevant evidence. No reset, second tracker or mandatory whole-project reread. |
| One-line bug fix with a known reproduction check | [Bug fix](../playbooks/bug-fix.md) | A brief scope/acceptance/check checklist and relevant regression evidence suffice. No required phases, planning skill or extra agents. |
| Same unsafe boundary mistake recurs | [Working rules](../skills/configure-agent-instructions/references/workflow.md#repeated-error-prevention) | Assess cost/risk; prefer structural prevention then static/tests/runtime enforcement, validate good/bad cases in target; reserve prose for remaining judgment. No tool is installed here. |
| Skill installed alone; no playbook or sibling skill is available | [Planning skill](../skills/plan-implementation/SKILL.md), [instructions skill](../skills/configure-agent-instructions/SKILL.md), [tooling skill](../skills/configure-project-tooling/SKILL.md) | Required guidance remains bundled in each skill; no root document or sibling skill becomes a runtime prerequisite. |

Local links and affected rules were reviewed through file reads/searches. Templates intentionally retain adoption placeholders; adopters must resolve them. This review supplies no empirical success rate, automated guarantee, executed verification result or live Codex/Claude Code discovery evidence.
